The problem: TCP collapses over satellite links.

SatLink fixes it with a custom UDP protocol (SLP) — selective repeat, adaptive RTO, SACK — so data survives 600 ms delay and 5% random loss.

The problem (GEO satellite)

  • RTT ~600 ms (36,000 km up + down)
  • Random radio loss 1–5% — not congestion, but TCP treats it as such
  • TCP throughput capped at window / RTT — 64 KB at 600 ms ≈ 0.87 Mbps
  • TCP halves sending rate on random loss — wrong assumption for satellite links
  • Result: slow, unstable telemetry over long-delay, lossy links

The answer: SLP (SatLink Protocol)

Reliable transport over UDP — full control of reliability mechanisms instead of relying on TCP assumptions.

  • Selective repeat — only missing packets resent, not whole window
  • Sliding window — sized from bandwidth-delay product (BDP)
  • Adaptive RTO — SRTT + RTTVAR with exponential backoff and Karn's rule
  • SACK bitmap — 4-bit bitmap for selective retransmission
  • CRC32 — over 24-byte header (version/type + payload len + terminal ID + seq + ack + bitmap)
